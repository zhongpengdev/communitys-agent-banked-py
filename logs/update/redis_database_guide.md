# 零基础搞懂：Redis 数据库的连接机制与工作流程

你非常细心！在关系型数据库（如 PostgreSQL、MySQL）中，我们的确必须先手动执行 `CREATE DATABASE xxx`，然后建表才能连接和使用。

然而，**Redis 的设计哲学完全不同**。在 Redis 中，你**不需要也无法手动去“创建”数据库**。

本文档将为你彻底解惑：在 `.env` 中写了 `REDIS_DB=0` 后，到底连的是哪、谁创建的、数据流向是什么？

---

## 1. 核心结论：Redis 默认自带 16 个数据库

当你成功启动一个 Redis 服务（`redis-server`）时，系统在后台已经**自动为你创建并准备好了 16 个默认的逻辑数据库**。

* **编号命名**：这些数据库没有名字，只有数字编号，从 **`0` 到 `15`**。
* **默认开启**：这 16 个数据库是开箱即用的，无需你运行任何特殊的创建指令。
* **空间隔离**：`0` 号数据库和 `1` 号数据库是完全物理隔离的。你在 `0` 号库里存的 Key，在 `1` 号库里是绝对查不到的（相当于多租户隔离）。

> [!NOTE]
> 16 个数据库是 Redis 的默认配置（由配置文件中的 `databases 16` 决定）。一般情况下，`0` 号数据库是全局默认库，直接连接使用即可。

---

## 2. 为什么不用“建表”和“建库”？（无 Schema 设计）

Redis 是一个 **无 Schema（无模式）** 的 Key-Value 内存高速缓存。
* **没有表（Table）结构**：Redis 内部没有“行”、“列”或“表”的概念。
* **写入即创建**：当你在 Python 中执行 `rpush(key, value)` 时，如果这个 `key`（如 `agent:session:123:messages`）在数据库中不存在，**Redis 会在内存中瞬间动态创建它，而不需要像 SQL 一样先建表定义结构**。
* **自动垃圾回收**：如果你清空或删除了 Key，Redis 会自动回收对应的内存，不需要进行繁杂的 DDL 维护。

---

## 3. 从零开始：Redis 连接与数据流向完整生命周期

当你运行项目，调用 `push_message` 时，背后的数据流动流程如下：

```
+------------------+
| 1. 启动 Redis 服务 | ---> 操作系统中启动 redis-server，默认在内存初始化 0-15 号逻辑数据库
+------------------+
         │
         ▼
+------------------+
|  2. 读取配置文件  | ---> Python 项目启动，dotenv 加载 .env 里的配置参数：
+------------------+      REDIS_HOST=127.0.0.1, REDIS_PORT=6379, REDIS_DB=0
         │
         ▼
+------------------+
| 3. 建立 Socket 连接| ---> `aioredis.ConnectionPool` 向 127.0.0.1:6379 发起 TCP 连接
+------------------+      在连接握手时，客户端自动发出指令：`SELECT 0` (切换至 0 号逻辑库)
         │
         ▼
+------------------+
| 4. 动态写入热记忆  | ---> 客户端调用 `redis_client.rpush("agent:session:123:messages", payload)`
+------------------+      Redis 收到指令，发现在【0号库】中还没有该 Key，于是：
                          ① 在 0 号库内存中动态创建该 Key 的双向链表 (List) 结构。
                          ② 将 JSON 消息塞入链表末尾。
```

## 4. 实用操作：如何切换和管理 Redis 数据库？

### A. 如何在代码中切换数据库？
如果你的项目有“开发环境”和“生产环境”，或者希望把“消息缓存”和“分布式锁”分开，你只需要在 `.env` 中修改数字即可：
```env
# 所有的聊天热记忆改存在 2 号逻辑数据库中
REDIS_DB=2
```
Python 代码在建立连接时会自动执行 `SELECT 2`。你的聊天记录就将完全存入 2 号库，不会受到 0 号库的任何数据干扰。

---

### B. 如何在命令行 (redis-cli) 里切换并查看？
你可以通过命令行亲眼看一看这 16 个数据库：

1. **进入命令行**：
   在 PowerShell 中运行 `redis-cli`。
2. **默认处于 0 号数据库**：
   此时命令行提示符为 `127.0.0.1:6379>`，代表你默认在 0 号库。
3. **切换到 1 号数据库**：
   输入 `select 1`：
   ```text
   127.0.0.1:6379> select 1
   OK
   127.0.0.1:6379[1]> 
   ```
   * 提示符变成了 `127.0.0.1:6379[1]>`，这明确告诉你，你已经切换到了 **`1` 号数据库**。
4. **查看当前库的所有 Key**：
   ```text
   127.0.0.1:6379[1]> KEYS *
   ```

---

### C. 如何快速清空数据？
在 Redis 中清理数据极快，但请注意区别以下两个命令：

* **`FLUSHDB` (清空当前数据库)**：
  如果你在 0 号库执行，它只会清空 0 号库的所有 Key。1 号库到 15 号库的数据完好无损。
  ```text
  127.0.0.1:6379> FLUSHDB
  OK
  ```
* **`FLUSHALL` (毁灭级：清空所有 16 个数据库)**：
  清空 Redis 实例中所有的 16 个逻辑数据库。常用于本地开发环境的一键重置。
  ```text
  127.0.0.1:6379> FLUSHALL
  OK
  ```
